RUN RECEIPT CONTRACT
Owner-side qualification tooling: run receipt recorder.
Python 3 standard library only. Ordinary defensive code: no root, no
mounts, no environment or sandbox mechanics. git is used only to read
HEAD and worktree state.

COMPONENTS
- recorder.py (producer): runs one command once and publishes a receipt
  plus its captured output log. The recorder emits a record of one
  observed run only. It emits no verdict about the run's meaning.
- recorder-checks.py (gate): 10 checks over the recorder, using real
  mechanisms only: a real git work tree, real subprocesses, a real
  timeout enforced by a real SIGKILL of the run's process group, and
  real existing files for the no-overwrite refusals.

RECEIPT FIELDS (version 1; the exact set, no more and no fewer)
- version: receipt schema version, 1.
- commit: the 40-hex HEAD of the working directory at launch, or the
  --commit override. Load-bearing: without it there is no receipt.
  GIT_* environment variables do not redirect it, and a repository
  whose work tree does not contain the working directory (as with
  core.worktree) refuses the run.
- worktree_clean: true or false from git status at launch, with
  untracked files and submodules always included whatever git config
  says (no core.excludesFile, nor the user-level ignore file git reads
  when that is unset, hides a file; the repository's own .gitignore
  files and .git/info/exclude still apply); false also when any index
  entry is marked assume-unchanged or skip-worktree, since git status
  does not look at those files (a
  sparse checkout therefore records false); null when the commit came
  from --commit, where the recorder establishes nothing about the
  worktree.
- argv: the exact argument vector that ran, element for element.
- cwd: the absolute working directory the command ran in. Recorded raw.
- started, ended: wall-clock UTC ISO timestamps of the run. NOT
  monotonic.
- runtime_seconds: the measured duration on a monotonic clock, rounded
  to milliseconds.
- timeout_seconds: the --timeout value, or null when none was set. Only
  a finite positive number is accepted; nan, inf and values of zero or
  less are refused before the command starts. Every receipt is strict
  JSON, never holding NaN or Infinity.
- timed_out: true exactly when the timeout fired.
- exit: the process exit code, or null when the run ended by a signal.
- signal: the signal number that ended the run, or null. A timeout
  usually ends the run with SIGKILL (9), but a natural exit can race
  the kill; whatever actually ended the run is recorded.
- output: {path, sha256, bytes} of the captured combined stdout and
  stderr log, published beside the receipt.

GUARANTEES
- Exact argv record. The vector that ran is the vector recorded.
- Monotonic runtime. runtime_seconds is measured on a monotonic clock,
  independent of wall-clock changes.
- No overwrite. An existing receipt path or output log path, including
  a symlink whose target is missing, refuses the run BEFORE the command
  starts. Publication is two atomic no-overwrite hard links, log first
  then receipt; after the receipt link the pair is complete. Two runs
  started together on one receipt path can both pass that check and
  both run; the later publication is then refused at its link, and
  nothing is overwritten.
- Frozen log. The published log is a frozen copy of the run's captured
  output: it holds what the run had written when the recorder froze
  it, shortly after the direct child exited (after a firing timeout,
  after the group kill). Output written later by surviving processes
  is not captured, and the cutoff under still-writing processes is
  not exact. The published log never changes after the receipt is
  written.
- Real timeout. A firing timeout sends a real SIGKILL to the run's
  whole process group; timed_out means the deadline fired, and exit
  and signal record how the run actually ended, since a natural exit
  can race the kill. The recorder exits 124 whenever timed_out is
  true.
- Exit propagation. Otherwise the recorder exits with the run's own
  code, or 128 plus the signal number when a signal ended the run. A
  staging cleanup failure after publication is a warning only.
- Interrupt. SIGINT, SIGTERM or SIGHUP sent to the recorder while the
  run is live sends a real SIGKILL to the run's whole process group;
  no receipt is published and the recorder exits 128 plus the signal
  number. A missing receipt never hides a live run, and a further
  interrupt cannot cancel the kill. An interrupt after the run ended
  can leave a log without its receipt; one after the receipt link
  exits 128 plus the signal number and says the receipt was published.

NON-CLAIMS
- A receipt records ONE OBSERVED run. It is not a minimum-runtime
  proof, not a benchmark, and not a performance bound.
- A receipt is not a CI result and replaces no CI; CI records its own
  runs.
- A receipt makes no supported-environment claim. Interpreters,
  dependency floors and platform support are the caller's to state in
  the run's own method text.
- started/ended are wall clock and can move with the clock; only
  runtime_seconds is monotonic.
- cwd and argv are recorded raw, including local absolute paths.
  Normalizing machine-specific paths is a separate publication step,
  never the recorder's edit.
- A receipt is not a signature and proves nothing about who ran it.
- An output log without its receipt is not a receipt and carries no
  meaning.
- The gate qualifies the recorder's own behavior only. It certifies
  nothing about any run the recorder records.

USAGE
    python3 recorder.py RECEIPT_PATH [--timeout SECONDS] [--cwd DIR] [--commit COMMIT] -- COMMAND [ARG...]
    python3 recorder-checks.py

Defaults: --cwd is the current directory; the commit comes from git
HEAD there. Outside a git work tree, --commit is required. The receipt
is written to RECEIPT_PATH and the captured output to RECEIPT_PATH.log.

CHECK DEFINITIONS (what the gate's 10 checks verify)
- R1: a passing run is recorded exactly - commit, argv, cwd, exit 0,
  and the output hash and bytes match the published log.
- R2: a failing exit code is recorded and propagated.
- R3: a real timeout kills the run's process group with a real
  SIGKILL; the child and a background descendant in its group are
  really dead, the receipt records timed_out, a null exit and signal 9,
  and the recorder exits 124. SIGINT, SIGTERM and SIGHUP to the
  recorder during a run kill the same group, publish no receipt and
  exit 128 plus the signal number. --timeout nan, inf, -inf, 0 and -1
  are refused before the command starts.
- R4: an existing receipt or an existing output log refuses the run
  before the command starts; the existing bytes are untouched. A
  dangling symlink at either path refuses it too, and stays as it was.
- R5: outside a git work tree with no --commit there is no receipt; a
  --commit override is recorded with worktree_clean null; a malformed
  --commit is refused.
- R6: a dirty worktree is recorded as worktree_clean false, not hidden,
  including an edit behind assume-unchanged or skip-worktree and an
  untracked file behind status.showUntrackedFiles=no; a GIT_DIR naming
  another repository changes neither commit nor worktree_clean, and a
  work tree moved by core.worktree is refused.
- R7: the receipt carries exactly the schema's fields, the timestamps
  are UTC and parse (their order is not checked: they are wall clock),
  and the printed receipt equals the published file.
- R8: the published log is frozen: a background descendant's later
  output never changes it, and the receipt hash still matches.
- R9: under a firing timeout with a setsid-escaped writer, the
  published log stays frozen, the hash still matches, and the
  recorder exits 124.
- R10: a runaway writer after the child's exit cannot keep the
  recorder copying forever; the recorder terminates with a bounded
  snapshot whose hash matches the published log.
